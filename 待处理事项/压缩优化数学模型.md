# 压缩优化数学模型 v3

> 通用压缩调度器的数学模型。不依赖特定框架，只通过有限可观测信号做决策。
> 所有成本项按**实际价格**（缓存命中/未命中区分计价）计算。
> 调度器作为独立模块，适配方自行实现接口。

---

## 基础变量

> 所有变量中，适配方需自行测量提供的标记为 [测量]；已知常数的标记为 [常数]；调度器内部维护的标记为 [调度器]。
> 未标记的为可推导变量。

### 会话参数 [测量]

| 符号 | 含义 | 说明 |
|------|------|------|
| S | 会话总轮数 | 从开始到结束的完整对话轮次 |
| Δ(t) | 每轮 token 增量 | **时变的**——受模型能力 λ、任务类型、工具包大小影响。λ↑ → Δ 偏小（强模型一轮到位，少试错）|
| M | maxContext | 上下文窗口上限（token） |
| T_sys | 系统提示词 token 数 | 正常对话的系统提示词，随工具包膨胀而增长 |
| T_user_avg | 每轮用户输入平均 token 数 | 不含历史部分 |

### 调度器参数 [调度器]

| 符号 | 含义 | 范围 | 说明 |
|------|------|------|------|
| τ | **压缩触发阈值** | (0.3, 0.9) | usageRatio > τ 时触发压缩 |
| δ | **压缩激进程度** | (0.1, 0.9) | 控制摘要详细程度，δ↓ 越激进 |
| β | **缓存破坏系数** | [0, 1] | 压缩操作导致缓存失效的比例，由策略和 δ 共同决定 |

### 价格参数 [常数]

| 符号 | 含义 | 说明 |
|------|------|------|
| P_full | 未命中缓存的 token 单价 | API 全价 |
| P_cache | 命中缓存的 token 单价 | API 缓存折扣价 |
| α | 缓存折扣因子 | α = P_cache / P_full，典型值 0.5 |

### 超参数 [用户配置]

| 符号 | 含义 | 范围 | 说明 |
|------|------|------|------|
| λ | **模型能力系数** | (0.5, 1.5) | λ>1 表示模型较强，λ<1 表示模型较弱。默认 1.0。影响 Δ、g(δ)、B(δ) 等观测量的基准值。用户根据自己使用的模型调节。 |
| T_comp_sys | 压缩专用提示词长度 | >0 | 策略 A 使用。如使用策略 B/C 则不需要。 |

### 函数定义

| 符号 | 含义 | 说明 |
|------|------|------|
| B(δ, λ) | 压缩后基线函数 | 摘要 token 数 + 保护区 token 数，δ↑ → B↑。λ↑ → 强模型摘要更精炼 → B 略小 |
| f(δ) | 压缩器输出函数 | C_comp_out = f(δ)，δ↑ → 摘要越长 |
| g(δ, λ) | **补课次数函数** | 压缩后模型回头补课的总次数。δ↓ → g↑；同一 δ 下，λ↑ → 更强模型更少补课 → g 更小 |
| β(策略, δ) | 缓存破坏函数 | β = β_strategy + (1 - β_strategy) × δ |

## 一、压缩策略与缓存破坏

三种压缩策略，缓存影响不同。

### 策略 A：独立压缩提示词

```
压缩器调用：
  system = 压缩专用提示词（长度 T_comp_sys）
  user   = 待压缩历史（长度 T_history）
  
  缓存状态：system 切换 → 缓存全失
```

| 缓存破坏 | system | user |
|----------|--------|------|
| 压缩调用 | × 全未命中 | × 全未命中 |
| 恢复对话 | × 全未命中 | × 摘要+近期全未命中 |

### 策略 B：复用系统提示词

```
压缩器调用：
  system = 正常提示词（长度 T_sys）→ 命中缓存
  user   = 待压缩历史 + 压缩指令（长度 T_history + T_instruction）
  
  缓存状态：system 命中；user 全未命中
```

| 缓存破坏 | system | user |
|----------|--------|------|
| 压缩调用 | ✓ 命中 | × 未命中 |
| 恢复对话 | ✓ 命中 | × 摘要+近期未命中 |

### 策略 C：伪装用户请求

```
压缩器调用（克隆当前对话后追加"请压缩"）：
  system = 正常提示词 → 命中缓存
  user   = 完整历史（与缓存一致）→ 命中缓存
  新增 = 仅"请压缩"指令
  得到摘要 → 从对话流中过滤掉，注入到实际位置
  
  缓存状态：system 命中；历史命中；仅 1 条新指令
```

| 缓存破坏 | system | user |
|----------|--------|------|
| 压缩调用 | ✓ 命中 | ✓ 历史命中；新增指令未命中 |
| 恢复对话 | ✓ 命中 | × 摘要+近期重新组织，未命中 |

### 缓存破坏系数 β

β 由策略和 δ 共同决定：

```
β(策略, δ) = β_strategy + (1 - β_strategy) × δ
```

| 策略 | β_strategy | 含义 | β(δ=0.5) |
|------|-----------|------|-----------|
| A | 1.0 | 始终全破坏缓存 | 1.0 |
| B | 0.4 | system 保留，user 破坏 | 0.7 |
| C | 0.15 | 大部分内容保留在缓存中 | 0.575 |

## 二、压缩器调用成本（实际价格）

### 策略 A

```
C_comp_A = (T_comp_sys + T_history) × P_full + C_comp_out × P_full

缓存恢复：system 不在缓存，user（摘要+近期）不在缓存
C_recover_A = T_sys × P_full + T_summary × P_full
```

### 策略 B

```
C_comp_B = T_sys × P_cache + (T_history + T_instruction) × P_full + C_comp_out × P_full

缓存恢复：system 在缓存（复用），user（摘要+近期）不在缓存
C_recover_B = T_sys × P_cache + T_summary × P_full
```

### 策略 C

```
C_comp_C = T_sys × P_cache + T_history × P_cache + T_instruction × P_full + C_comp_out × P_full

缓存恢复：system 在缓存，摘要内容可能部分在缓存（刚生成的）
C_recover_C = T_sys × P_cache + T_summary × (β × P_cache + (1-β) × P_full)
```

### 一次完整压缩的总成本

```
C_comp_total(策略, δ) = C_comp_策略 + C_recover_策略
```

## 三、压缩频率

```
Freq(τ) = 会话中压缩发生的总次数
```

一阶近似（线性增长假设）：

```
Freq(τ) ≈ (S × Δ) / (τ × M)
```

实际受摘要基线 B(δ) 影响，更精确的表达式：

```
每次压缩后的基线 token 数 = B(δ) = T_summary + T_protected_zone

两次压缩间隔轮数 = (τ × M - B(δ)) / Δ

Freq(τ, δ) = S / [(τ × M - B(δ)) / Δ] 
            = (S × Δ) / (τ × M - B(δ))
```

B(δ) 存在时，Fre 比一阶近似略大（τM - B < τM）。

## 四、压缩器总成本

```
CompressionTotal(τ, δ, 策略) = Freq(τ, δ) × C_comp_total(策略, δ)
```

## 五、历史臃肿成本（实际价格）

压缩间隔期间，每轮对话的输入包含：
- system prompt：始终命中缓存（不变化）
- 摘要部分：命中缓存（不变）
- 近期对话：随着轮次增加，新内容不断追加

```
压缩间隔内每轮的实际价格：

第 1 轮（刚压缩后）：
  system     = T_sys × P_cache
  摘要        = T_summary × P_cache
  近期对话(1) = T_near × P_full

第 n 轮（压缩后第 n 轮）：
  system     = T_sys × P_cache
  摘要        = T_summary × P_cache
  近期对话(n) = (T_near + n × Δ_near) × P_full
  
  其中 Δ_near 是新增的近期对话 token
```

整个压缩间隔的总历史成本：

```
HistoryCost_per_interval = 压缩间隔轮数 × T_sys × P_cache
                         + 压缩间隔轮数 × T_summary × P_cache
                         + Σ_{n=1}^{N} (T_near + n × Δ_near) × P_full

其中 N = 压缩间隔轮数 = (τM - B) / Δ
```

求和展开：

```
Σ_{n=1}^{N} (T_near + n × Δ_near) = N × T_near + Δ_near × N(N+1)/2
```

所以：

```
HistoryCost_per_interval = N × (T_sys + T_summary) × P_cache
                         + [N × T_near + Δ_near × N(N+1)/2] × P_full
```

乘以 Freq 得到全局历史成本：

```
HistoryCost(τ, δ) = Freq(τ, δ) × HistoryCost_per_interval(τ, δ)
```

## 六、补课成本（实际价格）

压缩后信息丢失（δ 太小），模型需要回头读取文件。

```
每次补课：
  system     = T_sys × P_cache（复用，命中缓存）
  read结果   = read_content × P_full（新内容，未命中缓存）
  回复输出   = reply_out × P_full（新内容，未命中缓存）

C_remedial_per = T_sys × P_cache + (read_content + reply_out) × P_full

总补课成本：
RemedialCost(δ) = N_remedial(δ) × C_remedial_per
```

N_remedial(δ) = g(δ)，δ↓ 时 g(δ) 急剧上升。

当连续补课时（多次 read 同一文件）：
```
第 1 次：全未命中
第 2 次（读同一文件）：read 内容可能部分命中（如果未被缓存驱逐）
```

## 七、缓存过期与窗口限制修正

当上下文使用率接近窗口上限时，缓存可能因窗口限制而自动失效。

```
if usageRatio > 缓存窗口 / M:
    缓存即将/已经失效
    压缩导致的缓存破坏成本 → 0（反正也要失效了）
```

引入修正因子：

```
γ = min(1, (缓存窗口 / M) / usageRatio)

修正后的缓存成本 = 原始缓存成本 × γ
```

- usageRatio 很大时，γ 很小 → 缓存的边际价值低
- usageRatio 很小时，γ = 1 → 缓存完整有效

## 八、总成本模型

```
TotalCost(τ, δ, 策略) = CompressionTotal(τ, δ, 策略)
                      + HistoryCost(τ, δ) 
                      + RemedialCost(δ)
```

展开：

```
TotalCost = Freq(τ, δ) × C_comp_total(策略, δ)
          + Freq(τ, δ) × HistoryCost_per_interval(τ, δ)
          + g(δ) × [T_sys × P_cache + (read_content + reply_out) × P_full]

其中：
  Freq(τ, δ) = (S × Δ) / (τ × M - B(δ))
  
  策略 A:
    C_comp_total = (T_comp_sys + T_history) × P_full + C_comp_out × P_full
                 + T_sys × P_full + T_summary × P_full
  
  策略 B:
    C_comp_total = T_sys × P_cache + (T_history + T_instruction) × P_full + C_comp_out × P_full
                 + T_sys × P_cache + T_summary × P_full
  
  策略 C:
    C_comp_total = T_sys × P_cache + T_history × P_cache + T_instruction × P_full + C_comp_out × P_full
                 + T_sys × P_cache + T_summary × (β × P_cache + (1-β) × P_full)
  
  HistoryCost_per_interval = N × (T_sys + T_summary) × P_cache
                           + [N × T_near + Δ_near × N(N+1)/2] × P_full
  
  N = (τ × M - B(δ)) / Δ
```

## 九、约束条件

```
τ ∈ (0.3, 0.9)
δ ∈ (0.1, 0.9)
β ∈ [0, 1]
B(δ) ≤ τ × M     ← 压缩后基线不能超过触发阈值
```

## 十、调度器接口设计

作为独立模块，对外暴露以下接口：

```
// 调度器状态（可序列化，持久化跨会话）
interface SchedulerState {
  τ: number;
  δ: number;
  stats: {
    totalCompresses: number;
    averageReadsAfterCompress: number;
    averageCompressTokens: { input: number; output: number };
    sessionCount: number;
  };
}

// 输入：每轮对话后调用
interface CompressionDecision {
  shouldCompress: boolean;
  δ?: number;               // 如果压缩，激进程度
  recommendedStrategy?: 'A' | 'B' | 'C';
}

// 初始化
function createScheduler(
  initialConfig?: {
    τ?: number;
    δ?: number;
    strategy?: 'A' | 'B' | 'C';
    α?: number;             // 缓存折扣因子，由适配方提供
  },
  state?: SchedulerState     // 持久化历史状态，用于冷启动
): Scheduler;

// 每轮对话后调用
function onTurn(
  usageRatio: number,         // 当前上下文使用率
  turnsSinceLastCompress: number,
  recentReadCount: number,    // 最近 N 轮中 read 次数
  avgTurnDelta?: number,      // 可选，最近 N 轮平均每轮增量
): CompressionDecision;

// 压缩完成后调用
function onCompressComplete(
  actualInputTokens: number,
  actualOutputTokens: number,
  summaryTokens: number,
  strategy: 'A' | 'B' | 'C',
): void;

// 获取当前状态（用于持久化）
function getState(): SchedulerState;
```

## 十一、需要埋点测量的量

| 量 | 用途 | 获取方式 | 适配方责任 |
|----|------|----------|-----------|
| Δ(t) | 每轮 token 增量 | 每轮记录输入+输出 token | ✓ |
| B(δ) | 压缩后基线 | 每次压缩后记录摘要+保护区 token | ✓ |
| T_sys | 系统提示词 token 数 | 初始化时计算 | ✓ |
| T_history | 压缩时待压缩历史 token | 压缩时记录 | ✓ |
| T_summary | 压缩摘要 token 数 | 压缩完成后记录 | ✓ |
| C_comp_out | 压缩器输出 token | 压缩时记录 | ✓ |
| N_remedial | 补课次数 | 压缩后 N 轮内统计 read 调用 | ✓ |
| read_content | 每次 read 返回 token 数 | read 时记录 | ✓ |
| reply_out | 补课回复 token 数 | 补课时记录 | ✓ |
| α | 缓存折扣因子 | API 定价文档 | ✓（已知常数） |
| P_full / P_cache | token 单价 | API 定价 | ✓（已知常数） |
| 缓存窗口大小 | 缓存有效期限制 | API 文档 | ✓（可选） |

## 十二、待定问题

1. **是否所有缓存成本都按 (P_full, P_cache) 线性折算？** 实际上有些 API 的缓存写入本身也有成本，是否要加入？
2. **跨会话学习机制**：是否维持全局 (τ, δ) 缓存，每次会话结束用积累的统计数据更新初始参数，以加速收敛？
3. **g(δ)（补课函数）的形态**：是平滑递减还是阶跃式？这决定了在线优化 δ 是否可行。
4. **τ 是否需要独立优化？** 还是固定 τ 只调 δ？如果 τ 固定，成本模型可以大幅简化。
5. **缓存窗口小于 M 的情况**：当缓存有效窗口 < maxContext 时，即使不压缩，缓存也会在 usageRatio 超过某个阈值后自动失效。这个阈值是否需要纳入模型？
6. **调度器是否需要在多种策略间动态切换？** 还是由适配方固定选择一种策略？
