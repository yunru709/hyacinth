# 回合回滚机制方案

> 需求：用户发一条消息 → 模型执行全部操作 → 模型回复。这一整轮叫一个**回合**（Turn）。当模型改错东西时，需要可靠地回退到上一回合或前 N 回合的文件状态。

---

## 一、术语定义

| 术语 | 含义 |
|------|------|
| **回合 (Turn)** | 用户发一条消息 → 模型执行所有工具调用 → 模型回复。一个完整的对话轮次。 |
| **回合缓存** | 环状缓冲区，存储最近 N 个回合的快照数据（默认 10 回合，最大 20 回合）。旧数据自动淘汰。 |
| **回滚 (Rollback)** | 撤销某个回合中模型所做的所有**文件变更**，恢复到该回合开始前的状态。 |

> **核心原则：回滚只处理文件变更。** 配置文件、系统设置等变更由于难以全面追踪（可能通过终端直接修改），回滚工具不做自动恢复，而是返回提示让模型自行检查和修复。

---

## 二、回合记录机制

### 2.1 回合开始时（框架自动）

1. **Git 自动 commit**（如果工作区有 git 仓库）
   ```bash
   git add -A
   git commit -m "auto: pre-turn-{turnId}"
   ```
2. **记录回合起始状态**：commit hash、时间戳、回合编号
3. 清空操作日志缓冲区

### 2.2 回合中（框架自动拦截写操作）

对有副作用的基础工具，执行前自动记录前置状态：

| 工具 | 记录方式 |
|------|----------|
| `write` | 执行前读取文件旧内容（如果文件已存在） |
| `edit` | 执行前读取文件旧内容 |
| `insert` | 执行前读取文件旧内容 |
| `bash` | 记录命令本身（不追踪终端内的具体写入，靠回合前后 diff 捕获） |

> 注意：不追踪 `update_config`、`json_edit` 等工具的配置变更。理由见核心原则。

### 2.3 回合结束时

- 将当前回合编号、preCommit hash、变更文件列表打包存入**环状缓冲区**
- 持久化到 `.agent/rollback/` 目录
- 在 git 中打 tag：`rollback-turn-{turnId}`

### 2.4 数据结构

```json
{
  "turnId": 7,
  "timestamp": "2026-06-17T18:30:00+08:00",
  "preCommit": "abc123def",
  "changedFiles": [
    {
      "path": "src/main.js",
      "action": "modified"
    },
    {
      "path": "src/utils/new.ts",
      "action": "created"
    },
    {
      "path": "config/old.json",
      "action": "deleted"
    }
  ],
  "commands": [
    "npm install axios",
    "python scripts/migrate.py"
  ]
}
```

## 三、回滚工具设计

### 3.1 `rollback_status` — 查看可回滚的回合

```
rollback_status()
```

返回：
- 当前缓存中的回合列表（编号、时间戳、变更文件数）
- 每个回合的变更文件摘要
- 每个回合执行的命令记录

### 3.2 `rollback` — 执行回滚

```
rollback(turns: 1)
```

**参数：** `turns` — 回退的回合数，默认 1（上一轮），范围 1-10。

**执行流程：**

```
rollback(1) 被调用
  ↓
1. 读取回合 7 的缓存数据
2. 执行 git checkout <preCommit>    ← 精确恢复所有文件
3. 清理回合 7 的缓存
4. 返回回滚报告
  ↓
模型拿到报告，检查 commands 列表和 own context
判断是否涉及配置变更，手动处理
```

### 3.3 回滚报告示例

```
🔄 已回退到回合 6 开始前的状态（回退了 1 回合）

✅ 文件变更已自动恢复（3 个文件）
  • src/main.js        ← 修改已恢复
  • src/utils/new.ts   ← 已删除
  • config/old.json    ← 已恢复

💡 当前回合执行过以下命令，请检查是否涉及配置/系统变更：
  • npm install axios
  • python scripts/migrate.py

💡 如有其它配置变更（渠道、设置等），请自行检查和恢复。
```

## 四、存储设计

```
.agent/
  rollback/
    turn-7.json     # 回合 7 的变更记录
    turn-8.json     # 回合 8 的变更记录
    ...
    index.json      # 索引文件
```

- **环状缓冲区**：最多保留 20 个回合。超过时淘汰最旧的。
- **持久化到磁盘**：重启不丢失。
- **git tag** 作为辅助标记。

---

## 五、边界情况

| 情况 | 处理 |
|------|------|
| 工作区无 git 仓库 | fallback 到文件副本快照（回合开始时复制整个目录到 `~/.agent/rollback/snapshots/turn-N/`） |
| 回退后 git 有冲突 | 优先用文件副本恢复，git 状态留给用户手动处理 |
| 回合中间手动 git 操作 | 不影响，框架只认自己打的 commit |
| 多回合回退 | 按编号从最新到最旧逐个回退 |
| 模型在回合中崩溃 | 下一回合开始时检测到未关闭的回合，标记为「异常终止」，保留已有记录 |
| 用户手动修改了文件 | 下一回合开始前检测 dirty 状态，先 commit 再继续 |

## 六、实现路线

### Phase 1 — 基础设施

1. 框架层添加「回合开始/结束」事件钩子
2. 回合开始时自动 git commit
3. 拦截 `write`/`edit`/`insert`，执行前读旧内容
4. 回合结束时写入 `.agent/rollback/turn-N.json`
5. 环状缓存淘汰逻辑（最多 20 个）

### Phase 2 — 回滚工具

1. 实现 `rollback_status` — 查看可回滚回合
2. 实现 `rollback` — git checkout 恢复 + 返回报告

### Phase 3 — 增强

1. 无 git 时的文件副本 fallback
2. `bash` 工具的回合前后 diff 捕获（执行前 diff→执行后 diff，自动识别被修改的文件）
3. 自动清理：超过 7 天的回合缓存可压缩归档
