# 旁路意图簇 — 上下文编排方案

> 版本: v1.1 | 日期: 2026-07-29 | 状态: 已审查（2 位审查员交叉验证）

## 一、目标

让旁路 orchestrator 的意图识别结果驱动 Zone 3（历史对话）的**选择性组装**：只将当前意图簇相关的内容注入上下文，无关内容不进入。历史消息按意图分簇，每个簇独立压缩，summary 按意图桶存储。

同时将意图标签作为下游训练数据的 `capability` 标签。

---

## 二、当前架构 vs 目标架构

### 当前

```
Zone 3 = summary（全局混合） + 全部历史消息（按时间）
旁路 orchestrator: 意图 → 仅用于 inject_hint 纠偏 + 记忆维护
```

### 目标

```
Zone 3 = summary[intent]（当前意图） + intent_cluster 消息 + 保护最后 N 轮
旁路 orchestrator: 意图 → inject_hint + Zone 3 编排 + intent 持久化
                                                      ↓
                                            训练数据 capability 标签
```

## 五、关键设计决策

### A. orchestrator 关闭时的处理

当 bypass 未启用时，`bypass_intent` 事件不写入 events.jsonl。训练数据清洗时：
- 有 `bypass_intent` 的 → 直接用 `capability` 作为标签
- 没有的 → 回退到后置标注（Agent 后处理），标记 `tagged_by: 'agent'`

### B. 意图切换时 summary 的处理

```
当前 coding → 用户切换话题到 chat:
    Zone 3 = summary.chat + chat 消息 + 保护最后 N 轮
    // summary.coding 保留在内存/磁盘，但不注入当前上下文
```

### C. 被压缩消息的标记

压缩后的消息**不丢弃**，追加 `_compressed` 字段：

```json
{
  "role": "user",
  "content": {...},
  "_compressed": {
    "intent": "coding",
    "summary_hash": "abc123",
    "compressed_at": "2026-07-29T..."
  }
}
```

### D. 与现有压缩器的兼容

现有 `SummaryStore` 的 `save/load` 仍支持旧格式（单字符串）。新格式为 `Map<string, string>` JSON 序列化。向后兼容——旧 summary 在首次读取时自动迁移为 `{ "general": "<原内容>" }`。

### E. BypassManager 数据链路修正 🔴

方案中缺少 `BypassManager` 的改动——`PreTurnResult` 新增 `intent` 字段后，`BypassManager.preTurn()` 的返回类型必须同步扩展：

```typescript
// bypass/manager.ts preTurn() 返回类型变更
async preTurn(ctx: PreTurnContext): Promise<{
  transformedInput?: string;
  injections: Injection[];
  intent?: { capability: string; confidence: number };   // 新增
}>
```

多个 bypass agent 同时返回 intent 时，取 `orchestrator` 的意图为权威来源；无活跃 agent 时 `intent = null`，Zone 3 回退为全量历史（不过滤）。

### F. 安全护栏 🔴

1. **路径遍历防护** — `clusterKey` 必须白名单校验：只允许 `[a-zA-Z0-9_-]{1,64}`
2. **LLM 输出净化** — `[CAPABILITY: xxx]` 解析结果在用于文件名/写入前做 sanitize
3. **日志脱敏** — orchestrator 日志中的用户输入做敏感信息（api_key、token、password 等）脱敏

### G. SummaryStore 渐进式方案 🟡

为避免波及面过大，SummaryStore 不改接口签名，改为新增包装层：

```
sessionDir/
├── summary.md              ← 旧格式（兼容）
├── summary.coding.md       ← 新增：coding 意图簇的 summary
├── summary.chat.md         ← 新增：chat 意图簇的 summary
└── ...
```

`SummaryStore` 内部新增 `getClusterSummary(clusterKey)` / `saveClusterSummary(clusterKey, text)` 方法，原有 `load()`/`save()` 不变。波及面从 `~100 行` 降至 `~30 行`。

### H. 分簇压缩预算策略 🟡

当某意图簇超预算时触发压缩。单簇预算分配：
- 默认：按 `totalBudget * 0.7`（留 30% 给其他 zone）
- 保护最后 N 轮不压缩（N 从全局配置读取，默认 6）
- 压缩后消息标记 `_compressed` 字段（仅保留**最近一次**压缩记录，覆盖而非追加）

### I. 意图缺失时的降级策略 🟡

- orchestrator 未激活 → `_currentIntent = null` → Zone 3 注入全量历史
- orchestrator 激活但意图解析失败 → `_currentIntent = 'general'` → 使用 `summary.general` + 全部历史
- 新会话无历史 → Zone 3 为空，无意图过滤需要

## 六、风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| orchestrator 意图分类不准 | 中 | Zone 3 可能漏掉相关历史 | 保护最后 N 轮兜底 + 可手动调整 |
| 意图频繁切换 → 缓存失效频繁 | 低 | 性能下降 | 大部分时间意图稳定；Anchor 层不受影响 |
| 旧格式 summary 迁移失败 | 低 | summary 丢失需重建 | 向后兼容逻辑 + 单元测试 |
| compressor 分桶后 token 计算不准 | 中 | 单簇超预算未被检测 | 每个簇独立做 token 预算检查 |
