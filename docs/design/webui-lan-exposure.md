## 三、唯一"缺"的一层：远端没有权限分级 ✗（但这是取舍，不是洞）

- 现状：WebUI 会话建的是 `normal` 路由 ⇒ 黑名单只有一项 ⇒ **远端会话手里是完整工具集**（含 bash、写文件、删除）✗
- 但触发条件是**主动行为**：必须显式绑对外地址 **且** 配好 apiKey ✓（默认两者都不满足 ✓）
- ⇒ 因此这是**有意的取舍**，不是漏洞 ✓；**要不要分级、按什么维度分级**（连接对端地址？会话标记？）由用户定 ✓

**建议的分级维度**（供参考 ✓）：应按**连接来源**（本机 vs 非本机）分，**不要**按渠道名分 —— 因为用户自己在同一台机器上用浏览器访问 WebUI 是常态 ✓，按渠道一刀切会误伤本机使用 ✗。

## 四、留给用户的两条决定（我未动手 ✓）

**决定一：免鉴权的只读端点要不要加短时签名？**
- 现状：`/api/health`、`/api/media*`、`/api/companion/*`、静态资源（`/`、`/index.html`、`/theme.css`、`/app.css`、`/app.js`、`/favicon.ico`、`/vendor/*`、`/assets/*`）**无需鉴权** ✓
- 设计理由**正当** ✓：浏览器 `<img>` / `<audio>` **无法携带** Bearer 头 ✓（与 WS 用 `?token=` 是同一个原因 ✓）
- 代价 ✗：绑到局域网后，**同网任何人都能拉走媒体库与陪伴场景** ✓（隐私面；**不涉及执行权** ✓ —— 拿不到 shell ✓）
- 建议 ✓：给这些 URL 发**短时签名**（与"一次性配对票据"同一套思路 ✓），既保留浏览器直读的便利，又不留长期敞口 ✓

**决定二：远端要不要做工具权限分级？**（第三节）
- 若做，建议按**连接来源**分；且**默认**：远端只读 ✓、危险工具（bash/写/删除）默认禁用 ✓、每条留痕 ✓
