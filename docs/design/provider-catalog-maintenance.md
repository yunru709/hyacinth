# Provider / 模型目录维护（设计草案 v0.2）

> 状态：**设计草案，未实施**（2026-09-30 与用户对定方向；v0.2 修订"用什么机制承载 LLM"）。
> 前提结论：新增厂商**已可免改代码**接入 —— `providers.json` 声明 baseUrl / protocol / envKey 即可用
> （`provider/factory-registry.ts` 的 `createJsonDeclaredFactory`）。
> 真正需要"跟着厂商变"的只剩一层：**模型元数据**（价格 / 上下文 / 最大输出 / 能力 / 模态），
> 现手写在 `provider/model-types.ts` 的 `MODEL_CATALOG`，并可由 `providers.json` 覆盖。

## 0. 一句话

代码与数据分离：**目录分三层**（手写 > 运行期缓存 > 出厂快照）；
日常刷新由**进程内的刷新器 + 脚本**全自动完成（**零 LLM**）；
只有出现"异常/拿不准"才唤起一次 **无会话的一次性 LLM 调用**；
落盘**只有一个写者（脚本）**。

## 1. 目标 / 非目标

**目标**

- 用户侧数据可自更新：厂商一变，不必等我们发版。
- 错数据不可静默进生效区（校验 + 门禁 + 留底 + 回滚）。
- 离线可用：不联网也能启动，也有兜底数据。
- **默认全自动**：无事时完全静默（不投消息、不烧 LLM、不留痕）。

**非目标**

- **不把厂商协议的实现搬出代码**。鉴权、请求变换、流式解析、响应字段怪癖仍属代码 ——
  变化频率极低，改一次发一次版可接受。可配置化的范围只到"地址 / 协议 / 字段名映射"这类**纯声明项**。
- **不引入新的"Agent 身份"**（见 §6）。

## 2. 地基（G 阶段 —— 先做，不碰任何外部数据）

| 编号 | 内容 | 验收 |
|---|---|---|
| G1 | 数据形状定死：字段清单 + 单位与货币 + "未知"的表示法 | 与现有 `MODEL_CATALOG` 字段对齐，**不另造一套** |
| G2 | 合并器：**纯函数**，三级优先级 + **逐字段回落** | 单测覆盖各级、以及字段级回落 |
| G3 | 目录布局定死：`~/.agent/catalog/`（当前生效 / 历史 / 探测结果 / 报告 / 待审清单 / 提案） | 人可读、可手改 |
| G4 | **唯一写者**命令：dry-run / 整份校验 / 写前留底 / 写后回读 | 校验不过 ⇒ 整份拒绝，不留半份 |
| G5 | 读路径改为三层，且**保持同步、永不联网** | 启动链路零网络依赖 |
| G6 | 守卫测试重定义：三处同源引用关系 | 改前改后都跑，禁止静默拆守卫 |
| G7 | 审计与回滚：版本号 + 来源 + 时间 + 变更摘要，可回退 N 版 | 一条命令回到上一版 |
| G8 | **新角色 `catalog`**：照 `compression` 角色的做法做"无会话一次性调用" | 一次调用进出，不进任何会话、不落历史 |
| G9 | **进程内刷新器**：与 watchdog 平级的进程组件（非 Agent） | 启动后异步跑一次；无事时零输出、零唤醒 |

G 阶段有一条硬验收：**不引入任何外部数据**，仅靠"手写一条覆盖"就生效 ——
且必须**活体验证**（单测证明不了加载路径真的走了新逻辑）。

## 3. 三层目录（优先级从高到低）

| 层 | 位置 | 写者 | 作用 |
|---|---|---|---|
| 手写 | `~/.agent/providers.json` | 用户 | 一票否决 |
| 运行期缓存 | `~/.agent/catalog/` | 同步脚本（提案来自 LLM 角色） | 日常新鲜度 |
| 出厂快照 | 源码 `model-types.ts` / `provider-meta.ts` | 维护者（发版时） | 断网兜底 |

合并语义：**逐字段回落**。用户写了某模型的价格 ⇒ 用用户的；只写了上下文 ⇒
上下文用用户的、价格取缓存。同一字段在三层都存在时，**上层永远赢**。

## 4. 刷新流水线

拉取 → 归一 → 交叉 → **审核** → **门禁** → 落盘 → 报告

| 步 | 谁做 | 说明 |
|---|---|---|
| 1 拉取 | 脚本 | 结构化目录（models.dev / LiteLLM，免密钥）+ 厂商"列模型"接口（用户 key） |
| 2 归一 | 脚本 | 对齐 G1 形状；货币与单位**显式标注** |
| 3 交叉 | 脚本 | 实测列表 vs 目录；目录里没有的标「元数据未知」，**不猜价格** |
| 4 审核 | **LLM 角色** | 只在有"待审项"时唤起；产出**提案文件**（见 §6） |
| 5 门禁 | **脚本** | 连通三档（§5）；**固定规则，不可交给 LLM**（否则不可复现） |
| 6 落盘 | **脚本** | 唯一写者；整份校验不过 ⇒ 整份丢弃 |
| 7 报告 | 脚本 | 动了什么、来源、时间、疑点 |

### 取数手段与失败处理

**手段（优先级从高到低 —— 能走接口就不爬页面）**

| 序 | 手段 | 说明 |
|---|---|---|
| 1 | **结构化接口** | `models.dev/api.json`（一次 GET，免密钥，实测 ~5.3MB）、LiteLLM 价格表（raw 文件）、厂商自带「列模型」接口（用户 key）、OpenRouter `/models`（免密钥） |
| 2 | **随包快照** | 出厂快照经 npm 分发（npm registry 在本机始终可达）—— **地板**：断网 / 被墙也退得回来 |
| 3 | **读官方页面** | 仅用于"既没接口、聚合目录也不收"的厂商（国内厂商、专属端点）。用现成的 `http_request`，**由 LLM 角色读**——它对页面改版比写死的选择器鲁棒；但提取值同样要挂证据、走字面命中校验 |

**原则**

- **抓不到 ≠ 数据变了**。这是最危险的一类误判（把"没抓到"读成"下架 / 无权限"）。
  必须区分「**没有证据**」与「**证据显示否定**」：前者保留旧值 + 标注未取得证据，后者才允许写。
- **失败分级**：
  - 429 / 5xx / 超时 / TLS ⇒ 指数退避 + 抖动重试；仍失败 ⇒ **保留旧数据 + 标注数据年龄**，下轮再试；
  - 401 / 403 ⇒ 该源需要凭据：用用户自己的 key 或换源，**不做绕过**；
  - 页面改版 ⇒ 解析失败 ⇒ 标「源不可用」交人工，**不猜**；
  - 长期不可达 ⇒ 退到随包快照。
- **多源交叉**：同一字段尽量有两个来源（聚合目录 + 官方接口 + 官方页面）；两源分歧 ⇒ 进待审清单交人工。
- **不引入灰色手段**：不上代理池、不绕 WAF、不破解验证码、不高频重试。
  宁可少一个源，也不让维护管线变成运维负担或风险源。
- **礼貌与频率**：24h 一次、带可识别 UA、不并发轰炸。
- **新鲜度可见**：报告与界面必须能回答"本份目录最后成功更新于何时、哪些源当期缺席"。

## 5. 连通门禁（三档，逐级加价）

| 档 | 做什么 | 成本 | 证明了什么 |
|---|---|---|---|
| L0 | 打一次"列模型"接口 | 免费、不耗 token | 地址 / 密钥 / 网络通 |
| L1 | 目标模型是否出现在返回列表里 | 免费 | 账号有权限 |
| L2 | 最小化一次真调用（极短输出） | **花用户 key 的钱** | 真能用 |

**规则**

- **L2 通过** ⇒ 标「已验证」，允许进生效区。
- L0/L1 过、L2 未过 ⇒ 只进**候选区**，不进生效区。
- **确定性否定**（模型不存在 / 无权限）⇒ 不写。
- **抖动不算失败**：网络错、限流、5xx 属可重试；**连续 N 次确定性失败**才降级。
- **增量**：只有新增 / 变动的条目跑 L2，存量不重复烧钱。
- **预算上限**：单次探测设有花费上限，超了自动停。
- **贵模型**：允许跳过 L2 并标「未实测」，由人放行（默认不放行）。

## 6. 机制：这活由谁来"想"（v0.2 修订）

**结论：不用子 Agent，也不用定时任务；用一个新角色承载"无会话的一次性 LLM 调用"。**

候选对比：

| 候选 | 本质 | 结论 |
|---|---|---|
| 子 Agent | 有**身份** + 有**会话**（会落盘） | ✗ 这件事不需要身份；且会挤进会话体系 |
| 定时任务 | 到点**往会话投一条消息**（`schedule/scheduler.ts` → 渠道投递，默认 feishu 兜底） | ✗ 必然产生对话回合，**无事也无法静默** |
| 旁路智能体 | 注入主 Agent 上下文，红线只准极窄工具 | ✗ `bypass/manager.ts` 明确禁止 `write` / `http_request` |
| **新角色（无会话一次性调用）** | 照 `compression` 的做法：专属通道 + 一次调用 + 产出制品 | ✓ **采纳** |

**执行形态**

- **进程内刷新器**（进程组件，与 lifecycle watchdog 平级）：调度复用现成的 `schedule/cron.ts`
  表达式解析。**无事 ⇒ 完全不输出**。
  **触发时机（2026-10-01 用户点头）**：
  ① 启动后**异步检查**（受 **24h TTL** 约束：距上次成功刷新不足则跳过，不下载）；
  ② 进程内 **24h 兜底定时器**（带随机抖动，覆盖长期不重启）；
  ③ 首次无缓存 ⇒ **强制刷**一次；
  ④ 手动命令（"刷新目录"）**忽略 TTL**；
  ⑤ 拉取**延迟到空闲**（距最后一条用户消息 > 2 分钟），不抢对话的带宽与 CPU。
  ⇒ 整条链上**只有"拉取 + 比对"（免费）是定时的**，其余全由变动 / 异常驱动。
  注：本程序非常驻服务 ⇒ **"每周几凌晨"这类定点调度不可靠**（没开机时那个点根本不存在），
  故用"启动检查 + TTL"自适应开机习惯，24h 定时器仅作兜底。
- **新角色 `catalog`**：照 `context/compressor.ts` 的 `createScopedProvider('compression', userId)` 模式 ——
  按**用户**分实例而非按会话；输入 = 待审清单文件（几 KB），输出 = 提案文件。**不进任何会话、不留历史。**
- 三处小改（属地基）：角色类型本就是开放的（`ModelRole = 'assessment' | 'planning' | 'compression' | string`），
  但 `gateway/tui-model-cmds.ts` 的白名单要补一项；通道角色映射加一条；刷新器接入启动装配。

**自动化的三层边界**

| 层 | 覆盖什么 | 需要什么 |
|---|---|---|
| 默认全自动 | 拉取、归一、比对、门禁、**只补缺且 L2 通过的直接落盘**、留底、报告 | 零 LLM |
| 异常路径 | 单位/货币可疑、量级异常、语义对不上、厂商别名映射、来源冲突 | 一次 LLM 角色调用 |
| 人工 | 覆盖已有值、放行「未实测」 | 用户点头 |

⇒ **LLM 的位置是"异常处理器"，不是"日常执行者"**。这是"只有 Agent 才能处理突发"的正确安放。

### 防幻觉：证据链（硬约束）

> 「LLM 会有幻觉 ⇒ 一切**以上下文里提供的厂商/模型信息为准**，不许凭自己的感觉。」
> （2026-10-01 用户指定）

光在提示词里写"不要幻觉"是没用的（谁都会说自己没幻觉）。要让这条**可校验**，就得把"依据"变成**外键**：

1. **证据集**：每次运行把所有抓取物落成一份带 ID 的证据集 ——
   每条 = 证据 ID + 来源 URL + 抓取时间 + 原文片段（或哈希）。
2. **逐字段挂出处**：提案里每个字段值都必须引用证据 ID。
3. **机械门禁**：脚本校验证据 ID 必须存在于**本次**证据集；
   数字类字段还要求能在该证据的原文里**字面命中**。命不中 ⇒ **整条拒绝**。
   ⇒ "凭记忆写"的条目**物理上过不了校验** —— 它在证据集里找不到出处。
4. **无证据 ⇒ 只能留空或标「需人工确认」**，绝不用先验知识补值。
5. **先验知识的唯一合法用途 = 起疑**（"这个量级看着不对" ⇒ 触发人工复核），
   **绝不用来填数**。
6. **旧值不是真值**：上下文里的"当前生效值"只用于算差异，不能当基线抄写。
7. **抓取失败就承认失败**：官方页取不到 ⇒ 标「本期未取得证据」，
   **不许退回"我记得"**。

## 7. 分工

- **脚本（确定性）**：搬运、合并、探测、校验、落盘、留底、出报告。**唯一写者**。
- **LLM 角色（判断）**：字段语义对齐、别名映射、**单位与货币核对**、异常值、
  来源与时间标注、疑点清单。产出物是**变更提案 + 依据 + 疑点**，不是要直接写盘的内容。
- **用户（点头）**：覆盖类变更、「未实测」条目的放行。

## 8. 设计律

1. **目录 ≠ 启用** —— 目录里发现一家厂商，不自动接入；用户显式声明才算。
2. **单一写者** —— LLM 不直接写盘，只出提案。
3. **只增不删** —— 模型下架标「已弃用」，不删（删了会让配过它的人当场坏掉）。
4. **不懂留空** —— 拿不到就空着，**绝不猜价格**（价格直接决定钱包与上下文阈值）。
5. **门禁先于落盘** —— 没测通的条目，物理上进不了生效区。
6. **上游只当建议** —— 第三方目录可能错、可能滞后、可能被投毒 ⇒ 一律走门禁 + 审核。
7. **无事即静默** —— 后台维护不许在正常运行时产生任何可见噪声。
8. **确定性的事不交给概率性的东西** —— 探测判定、校验、落盘一律脚本。
9. **无出处不落笔** —— 提案的每个字段必须引用**本次**证据集里的条目；
   无证据只能留空或标「需人工确认」；**先验知识不得用于填数，只能用于起疑**（见 §6「防幻觉：证据链」）。

## 9. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **G** | 地基（§2） | 手写一条覆盖即生效（**活体验证**） |
| **P0** | 只报告不写盘：拉目录 → 与出厂快照对比 → 出报告 | 能指出价格是否对得上、哪家没匹配上 |
| **P1** | 刷新器 + L0/L1 门禁 + 提案落盘（只补缺、留底、可回滚） | 落盘后可回退；三层优先级活体验证；**无事时零噪声** |
| **P2** | `catalog` 角色接入（异常路径）+ L2 真调用探测 | 用一个真 key 跑通一家没接过的厂商 |
| **P3** | 通知（只在需要点头时打扰）+ 界面查看 / 采纳 | 报告出现在常用界面 |

## 10. 已知风险

- **加载器是同步的**（`ModelCatalogLoader.load()` 读到即缓存）⇒ 网络刷新**绝不能进启动链路**，
  只能"外部异步刷 → 文件落地 → 重载"。
- **守卫测试**锁着三处同源引用关系，动它要连带改，别把守卫悄悄拆了。
- **配置变更会向所有会话回声**（配置中心老毛病）⇒ 刷新通知要克制、按本会话去重。
- **dist 产物**：改 `src` ⇒ `build` ⇒ `restart` 才生效。
- **单位 / 货币静默错**是最危险的失败模式（¥/M vs $/M），必须有显式字段 + 人工审核兜底。
- **别把刷新器塞进旁路智能体**（`bypass/` 的安全红线明确禁止 write / http_request）。

## 12. 施工要点（附录）

### A. 数据形状（G1）：在现有 `ModelCatalogEntry` 上补什么

现有字段（`provider/model-types.ts`）：`id / name / provider / contextWindow / maxOutputTokens /
sampling? / capabilities{streaming, toolCalling, thinking, vision, inputTypes} / cost?{input, output, cacheRead?, cacheWrite?} /
status / replacedBy? / reasoning? / reasoningEffort?`

**必须补的**：

| 缺什么 | 为什么非补不可 |
|---|---|
| **`cost.currency`（USD / CNY）+ `cost.per`（每多少 token，默认 1M）** | 现在是**裸数字**——结构上挡不住"美元与人民币混写"。这是本方案最危险的失败模式，必须在 schema 层解决，而不是靠人盯 |
| **`source`（证据 ID）+ `observedAt`（观测时间）** | 没有出处就无法执行 §6「无出处不落笔」，也无法回答"这条是谁说的、什么时候说的" |
| **`verification`（已验证 L2 / 仅可见 L1 / 未实测）** | 门禁结果要能落进数据，否则"通过才允许更新"无从体现 |
| `deprecatedAt`（可选） | 配合"只增不删"，标记弃用时间 |

### B. 高危字段：有行为后果，默认只提议不落地

**证据在代码里**：`model-types.ts` 中 `deepseek-v4-flash` 那条注释写着 —— 曾因这里声明 `vision: false`，
provider 会**静默丢掉图片部分**（不报错）。

⇒ 结论：**这类字段不是展示性数据，它有行为后果。**

| 字段类 | 权限 | 理由 |
|---|---|---|
| `capabilities.*` | **只提议，不自动落** | 写错会改变"发给模型的内容"（静默丢图） |
| `contextWindow` / `maxOutputTokens` | **只提议，不自动落** | 写错会改变压缩阈值与截断行为 |
| `cost.*` | 只补缺时可自动落 | 影响的是花销可见性，不改行为 |
| `name` / `status` 等展示项 | 可自动落 | 无行为后果 |

### C. 目录布局（G3）

```
~/.agent/catalog/
  current.json          生效的运行期目录（只由脚本写）
  history/<ts>.json     历史版本（保留最近 N 份，供回滚）
  evidence/<run>.json   证据集：本次运行的全部抓取物 + 来源 URL + 时间 + 原文片段
  review/<run>.json     待审清单：给 LLM 角色的输入（**只含有疑问的条目**，不是全量目录）
  proposal/<run>.json   提案：LLM 角色的输出（逐字段挂证据 ID）
  reports/<run>.md      人类可读报告
  aliases.json          厂商别名映射（我们 id ↔ 上游 id）
  state.json            运行状态：上次成功刷新时间、各源健康度、TTL 判定结果
```

### D. 三件交换文件的边界

- **证据集**：只由脚本写，LLM 只读（它是"事实的落点"）。
- **待审清单**：脚本产出，**只含有疑问的条目**（几 KB）——不是把 5MB 丢给模型。
- **提案**：LLM 产出，每条 = 目标 + 字段 + 新值 + **证据 ID** + 置信度 + 疑点说明；
  **只有通过脚本校验才可能落盘**。

### E. 别名映射

`aliases.json`：我们内部 provider id ↔ 上游目录键（如 `gemini` ↔ `google`）。
规则：**显式表优先；未命中 ⇒ 标「未匹配」交人工，不做模糊猜测。**
