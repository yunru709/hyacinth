## 一、已定的决策

1. 桌宠**属于我**（同一身份、同一份记忆），**不是**独立 agent。
2. **任意渠道**都有能力**访问并接手**这具身体的动作（TUI / webui / 飞书 / 微信 …）。
3. 也能**通过这具身体推送运行情况** —— 例如冒个气泡发一句话。
4. 身体是**独立进程**（本地循环，**不含 LLM**）。

---

## 二、为什么不是"独立桌宠 agent"

- **记忆与人设是全局的**（同一份文件）。另起一个 agent ⇒ 要么它不知道我在干什么，要么得再造一套记忆体系 ⇒ 观感变成"两个我"，比"我有身体"差得多。
- **独立不省 token**：省的是**唤醒频率**，不是进程边界。这是一个容易想反的点。
- **例外**：若将来要的是"**另一个住户**"（另有性格与记忆的独立存在），那属于**角色问题**（陪伴模式已有"创建角色"的机制），与本稿不是一回事，另议。

> 归属判断：**身体独立、脑子共用**。即"挂在我上面"，但身体不在我进程里。

---

## 三、四个必须成立的硬约束

| # | 约束 | 为什么 |
|---|---|---|
| 1 | 身体是**独立进程** | 实时循环与动画（以及它可能的崩溃）不该拖住我 |
| 2 | **会话独立、记忆共用** | 对话历史按会话走；长期记忆与身份全局共用 |
| 3 | **心跳不叫我** | 本地循环管"动"（快、笨、免费）；我按**分钟级**醒；只有**用户交互**或**真偏离**才即时唤起 |
| 4 | **动作守门** | 能点鼠标/按键 = **不可逆** ⇒ 白名单 + 留痕（"补边界"那类不变量在这里从可选变必需） |

## 四、两条新要求带来的机制结论（本轮新增，最有价值的部分）

### 4.1 "任意渠道接手身体" ⇒ 需要**接管者 + 租约**

- 同一时刻两个渠道同时驱动 ⇒ **指令互相打架**（一个让它往左、一个让它往右）。
- 因此需要两个概念：**接管者（owner）** 与 **租约（lease）**；非接管者只能**看**或**排队**。
- 抢占优先级建议：**用户直连 > 定时任务 > 后台自主动作**。
- 已有先例：`session-lock`（同一资源互斥）；渠道路由（`getRouterNameForChannel`，按渠道判模式）。

### 4.2 "冒气泡推送" ⇒ 气泡是 **live 输出，绝不进任何会话的历史**

- 依据（今晚的教训）：一张 609KB 的图进了历史 ⇒ **每轮重发**、把上下文吃光 ✗。气泡比图**更频繁**，落历史就是灾难。
- 故气泡与**记事本、媒体剥离**同族：**请求时装配、不进历史**。
- 推送**复用现有投递面**（"借用渠道发消息"那套），**不另造一套**。

## 五、形态（一句话）

**身体 = 设备**（有状态、有所有权），**不是渠道**。

- 渠道 = **输入口**
- 身体 = **动作口 + 输出口**
- 驱动路径：渠道 → 工具（感知 / 动作）
- 推送路径：运行情况 → **live 输出面**（气泡）

---

## 六、建议的实施次序

**先做"只有嘴、没有手"的版本** ✓：
只读感知（窗口 / 鼠标位置 / 时间）+ 会说话 + 定时主动找人，**不给点击权**。
理由：这一步**几乎不需要新机制**（渠道 + 定时任务 + 陪伴模式都在），成本可控，而且验到的是**最难的部分 —— 交互的感觉**；动画与四肢是最容易的部分，也最该最后做。

第二步再谈"手"（动作 + 守门），届时前一步会暴露真实需求。

## 七、开放问题（未定，别当成已决）

1. **传感器词汇表**：先只读（窗口/鼠标/时间）够不够？要不要屏幕？
2. **便宜模型**：桌宠是否该用更小的模型（需"**模型选择粒度下沉到会话**"—— 这是 `context/profiles.ts` 头部已写明的两件前置改造之一，目前还没有）。
3. **心跳节律的具体值**：先定"分钟级"，具体值待实测再定。
4. **气泡与"待办提醒"是否合并**：两者都属 live 通知，可能是一套。
5. **现有陪伴角色的记忆是否分文件**：未核实；若不分开，则"多角色独立记忆"才是真需要新造的东西。

## 八、判据（可验 —— 用来判定做得对不对，而不是好不好看）

- 若**我每轮上下文都被桌宠的事塞满** ✗ ⇒ 硬约束 3（心跳不叫我）没做对。**这是最可能的失败方式。**
- 若**它问的问题我自己都不知道答案** ✗ ⇒ "记忆共用"没做到。
- 若**两个渠道能让身体同时做相反的事** ✗ ⇒ 租约（4.1）没做对。
- 若**气泡出现在某会话的历史里** ✗ ⇒ 4.2 没做对（会重演上下文吃光）。

---

## 九、有意不做的事

- 不另起独立 agent（除非将来明确要"另一个住户"）。
- 不在"只有嘴"的版本验证之前给它点击权。
- 不为桌宠新造推送通道（复用现有投递面）。
- 不把身体做成"渠道"（它是设备；渠道是输入口）。
