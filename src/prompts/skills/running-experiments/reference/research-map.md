# 参考 · 研究地图（问题树）

> 上游：SKILL.md §4.2。**触发**：新研究且存在多条候选路线，或需做推进 / 剪枝 / 转向决策时强制建树；纯复现可降级为台账 + `parent_experiment` 链。本文件规定这棵树**存什么、怎么维护、何时更新**；它不存结论数字（数字归 `experiments-ledger.md` 与 `runs/`）。

## 1. 为什么必须有树

- 引用图 / 相关工作只证明「**可以移动**」——这条边**存在**（有人到过）；**不标识**它是**走过来**的（铺好的路）还是**爬过来**的（塌方独木桥）。
- 台账只回答「**跑过什么、结论如何**」，不回答「**还有哪些没跑、该往哪走**」。
- 树补的正是这两块：**可通行性**（节点可靠性）+ **frontier**（未跑分支与推进顺序）。缺了树，§4.2 的「重排 frontier」「pivot 计数」「最小深度 k」都无对象可操作。

## 2. 节点 = 一个可判真假的命题 / 子问题

每个节点**必填**下表字段；**缺字段 = 树未建完**。

| 字段 | 说明 |
| --- | --- |
| 命题陈述 | 一句话，可判真假 |
| 支撑强度 | **走过来**：严格证明 / 多路独立复现 / 已独立验证；**爬过来**：单源 / 类比外推 / 有已知 gap / 未复现 |
| 真值 | 未定 / 已确立 / 存疑 / 已证伪（只能由台账中的实验结论推出，不得凭判断直接写） |
| 工作状态 | 开放 / 进行中 / 已剪枝 |
| 反坍缩栏 | 见 §3，**每节点必填** |
| 最弱假设 | 该命题成立所依赖的最脆弱的一环 |
| 指向 | `实验ID`（→ 台账 / `runs/`）；**不写数值结论** |
| 预算盒 / pivot | 该枝的预算余量与转向计数 |

- **地基节点**：定义层 / 公理 / 被 ≥2 路独立验证者 → 标 `[地基]`，**冻结、不质疑**。
- **已剪枝节点保留不删**（记剪枝理由 + 日期 + 剪枝时的判据数值所在台账行），供环境变化后 re-expand。

## 3. 反坍缩栏（核心）

LLM 沿训练语料里最可能的续写方向收敛，即在语义空间里**坍缩到最主流的那一枝**——面对一个开放命题，它倾向默认去「证明它」，而不会自发去「证伪 / 减弱 / 推广 / 找反例」。对策是**在每个节点显式写下**：

```
【反坍缩检查】
- 兄弟分支：父节点的其他子方向（至少列 1 个，哪怕没跑）
- 反向操作：证明 ↔ 证伪 ↔ 减弱（弱化条件）↔ 推广 ↔ 反例（至少列 1 个）
- 被主流叙事遮蔽的旁支：（至少列 1 个；确实没有时写「无」并附理由）
```

**纪律**：
- 三栏**每栏不得留空**。确实无内容的栏只允许写「无，理由：……」，理由须具体（例：「父节点为纯定义，无兄弟」），空泛理由（「暂无」「不适用」）视为未填。
- 在任一节点上做**推进 / 剪枝 / 质疑**决策前，必须先回答这三问并落盘；**未填反坍缩栏不得做决策**。

## 4. 两种基本操作

- **向下探索**（默认）：在子节点继续细化 / 做实验。
- **向上质疑**：回头审视父节点是否成立。
  - 触发条件：父节点支撑强度是「**爬过来**」，或它是当前依赖链上的**最弱环**。
  - 意义：整棵树可能只长了「证明」一枝，**从来没人质疑根命题本身**；回头质疑父节点可能直接解决问题（换枝 / 证伪），而不是在错误枝上越走越深。
  - **校准（防过度质疑）**：
    1. 只质疑「爬过来」或最弱环节点；`[地基]` 节点**不质疑**。
    2. 质疑前先估**前瞻收益**：若父节点被证伪，下游计划中有多少预算需要改道、改道后能否更快得到结论。**预计改道收益明显大于质疑成本**时优先质疑；否则继续向下。该估计写入 frontier 重排记录。注意：已投入的历史成本不计入（沉没成本中性，见 SKILL.md §4.2）。
    3. 不得因为「想质疑」就动摇已被多路独立验证的基础结论。

## 5. 建树流程（研究开始前）

1. 以**核心问题**为根。
2. 检索前人工作，把已有结论 / 方法 / 反例整理为树，逐节点标注支撑强度（走过来 / 爬过来）并填反坍缩栏。
3. **定位**：写下「我们要研究的问题，位于哪个子节点」——是兄弟分支？某个反向操作？还是往下细化？
4. 冻结 `[地基]` 清单。
5. 允许**先花一笔预算**建树；产出 = `research-map.md` + 定位说明。

## 6. 维护纪律（与台账的分工）

| | `research-map.md`（前瞻 / 战略） | `experiments-ledger.md`（回顾 / 转置表） |
| --- | --- | --- |
| 存 | 候选路线、**未跑**分支、预算盒余量、pivot、剪枝理由 | 已跑实验的**结果、结论、证据强度** |
| 谁写 | AI 手动维护（结构与判断） | **数值列由脚本从 `runs/` 生成**；判断列（结论、状态、剪枝理由）由 AI 填写并注明来源文件 |
| 何时更新 | 每次 §4.2 决策（继续 / 转向 / 剪枝 / re-expand）后 | Step 7 落盘 |

- 树节点**只存指针 + 战略元数据**，指向台账实验ID；**任何数值结论不回填进树**——数据永远单源。
- 每次 frontier 重排**记一笔**（谁上谁下、依据哪个判据、判据数值来自哪个台账行），否则「重排」又变回凭感觉。

## 7. 小示例

```
[根] 方法 X 能提升任务 T 的指标 M          [开放]
├─ 证明 X 有效                              [进行中]  ← 只长了这一枝（坍缩）
│   ├─ 消融：X 中哪部分起作用                [开放]
│   └─ 超参敏感性                            [开放]
├─ 【反坍缩】X 是否在条件 C 下失效            [开放]  ← 反向操作：反例
└─ 【反坍缩】邻域方法 Y 是否已覆盖 X 的收益    [开放]  ← 被遮蔽旁支
```

某节点填充示例：

```
命题陈述：X 的增益来自组件 G
支撑强度：爬过来（仅本组一次实验，未独立复现）
真值：存疑　工作状态：开放
反坍缩栏：兄弟=「增益来自数据量」「增益来自调参」；反向=去掉 G 看是否掉点；旁支=同类方法用 G 未见增益
最弱假设：G 与额外算力未解耦
指向：exp-014（台账）
预算盒：2 GPU 时；pivot：1（换过一次实现）
```

- 示例中「反向操作」「被遮蔽旁支」两枝即**反坍缩产物**——若无强制，它们不会被写出来。
- 注意「支撑强度：爬过来」→ 提示「可向上质疑」，或先加固该节点再向下，而不是直接在其上建更多子节点。
