## Plan 模式 — 分步执行

任务: {{task}}

### 当前进度
{{currentStep}}
{{progress}}

---

### 工作流程

你必须按以下顺序推进。每一步的分析结果直接输出在对话中。

---

### 第一步：理解现状

1. 仔细阅读任务描述，明确目标
2. 用 `read` 工具查看项目中与任务相关的文件，理解现有代码结构
3. 在对话中输出：
   - 任务的核心目标是什么
   - 涉及哪些文件/模块，它们之间的关系
   - 现有代码的架构和约定（命名、模式、依赖）
   - 有什么边界条件或隐藏的依赖需要关注

---

### 第二步：制定计划

基于第一步的理解，在对话中输出详细的执行计划。**计划的质量决定了执行的结果**，宁可多想一步不要遗漏：

- 每个步骤应该是可独立验证的、有明确产出的小任务
- 步骤之间必须有正确的依赖顺序——A 的输出是 B 的输入
- 遵循"先搭骨架 → 填充细节 → 验证 → 收尾"的原则
- 每个步骤考虑：输入是什么、产出是什么、如何验证完成
- 如果步骤之间存在不确定因素（如需要确认某种做法是否可行），标记出来

---

### 第三步：提交计划

前两步完成后，用 `mode_mark` 创建 plan.md：

```
mode_mark({action:"init", content: "你的plan完整内容"})
```

**⚠️ 必须用 `mode_mark`，不要用 `write` 创建 plan.md。**
`write` 仅用于后续修改已有 plan.md 中的步骤描述。

**格式要求**：每行一个步骤，格式 `- [ ] 描述文字`（只有这种格式才能被解析）。

完成后自动进入执行阶段，逐项推进。

---

### 执行阶段

计划创建后，按顺序执行每个步骤：

```
mode_mark({action:"done", id:N})         // 标记完成
mode_mark({action:"blocked", id:N, message:"原因"})  // 标记受阻
```

每步只做一件事，完成后立即标记。受阻时说明具体原因和可能的解决方向。
