## Spec 模式 — Phase 1: 需求分析与方案设计

任务: {{task}}
文件目录: {{specDir}}

### 工作流程

你必须按以下顺序推进，**先思考再产出**。每一步的分析结果直接输出在对话中。

---

### 第一步：需求理解

1. 先通读任务描述，用 `read` 工具查看项目相关代码，理解现有架构
2. 在对话中输出你的理解：
   - 需求边界：做什么、不做什么
   - 关键实体/模块及其职责
   - 核心交互流程（可以用文字描述或简单的数据流）
   - 已明确的前提和待确认的假设

---

### 第二步：方案设计

基于第一步的理解，输出设计方案：
- 整体架构：模块/组件划分，各自职责
- 关键技术选型及理由
- 数据结构和接口设计
- 如果存在多种可行方案，简述各自的优缺点并给出推荐
- 识别主要风险和不确定点

---

### 第三步：产出文档

前两步分析完成后，用 `write` 分别创建三个文件（目录已由 Workflow 自动创建）：

```
write({file_path: "<specDir>/spec.md", content: "..."})
write({file_path: "<specDir>/tasks.md", content: "..."})
write({file_path: "<specDir>/checklist.md", content: "..."})
```

各文件内容要求：

**spec.md** — 规格文档：
- 项目概述与目标
- 技术栈和依赖
- 模块/组件划分及职责
- 数据流和接口定义
- 关键交互流程说明
- 边界条件和约束

**tasks.md** — 执行任务（多级结构）：
- 先按任务大类分为若干"部分"，用 `## 第N部分: 标题` 标记
- 每部分下面列出具体可执行步骤，每行格式 `- [ ] 描述`
- 步骤粒度适中（不是一行"完成整个功能"，也不是一个函数写一条）
- 整体遵循"先搭骨架 → 填充细节 → 联调测试"的顺序
- 每个步骤应该是可独立验证的、有明确产出的小任务

示例结构：
```
## 第一部分: 数据层搭建
- [ ] 定义数据模型和接口
- [ ] 实现数据存储层

## 第二部分: 业务逻辑
- [ ] 实现核心处理函数
- [ ] 添加错误处理

## 第三部分: 集成与测试
- [ ] 连接各模块
- [ ] 编写集成测试
```

**checklist.md** — 验收清单：
- 逐条对照 spec.md 中的功能需求
- 每行格式 `- [ ] 验收项`，每条可客观判定通过/不通过
- 覆盖正常路径、边界情况、异常处理

---

完成后推进到 Phase 2：
```
workflow({action:"step", id:0, stepAction:"done"})
```
